# Dog Team 2: research and graph work in progress

School project with static HTML charts, published with GitHub Pages at
https://lauraokas.github.io/dog-abandonment-korea/

## Files
- `index.html`: landing page that links to every chart. Add a link here for each new chart.
- `dutch-dog-timeline.html`, `korean-dog-timeline.html`: the timelines.
- `theme.css`: shared colours and fonts (light only). All pages link to it.
- `data/`: one data file per country (`korea.js`, `netherlands.js`) plus `categories.js`, all in the same format. Read `data/README.md` before changing them. Korea is the main country. Run `python3 tools/check-data.py` after every edit to the data.
- `timeline.html` is the combined timeline: one block per category, one row per country inside it (Korea first), one shared year axis, a compressed or even time scale, and a reading panel. It reads `data/*.js` through script tags, so a new country is one data file plus one `<script>` line. The two old pages (`korean-dog-timeline.html`, `dutch-dog-timeline.html`) are earlier versions that stay until the user says to remove them.

## Keeping the style consistent
- Every page must include `<link rel="stylesheet" href="theme.css">`.
- Use the CSS variables from `theme.css` (`--bg`, `--panel`, `--ink`, `--ink2`, `--line`, `--accent`, `--f-display`, `--f-body`, `--f-mono`). Do not hardcode colours or font names.
- The project palette is Yellow `#fffc31`, Vintage Grape `#5c415d`, Ivory `#f6f7eb`, Fiery Terracotta `#e94f37`, Gunmetal `#393e41` (the user's own choice; defined in `theme.css`). The page background is a lighter ivory (`--bg`, `#fcfcf6`). Grape is the link/accent text colour, gunmetal is the text colour.
- Timeline categories are shared by every country (the user chose these names and wants them kept short): origins `--c-origins` (magenta), role `--c-role` (teal), meaning `--c-meaning` (rose), ownership `--c-ownership` (vermilion), law `--c-law` (indigo), breed `--c-breed` (emerald). Companion and bond sits under Meaning (the user's decision). The older names (`--c-food`, `--c-ritual`, `--c-hunt`, `--c-bond`) only exist for the two old pages and are removed when they are replaced. Colours must be vivid (the user asked for "more vibrant") and far apart, because they appear as tiny dots: a new category colour must be as saturated as the contrast rules allow and differ from every existing one by at least 30 in CIELAB distance (compute it). Never use yellow, or a darkened yellow or ochre, for a category (the user dislikes it).
- Yellow is the accent colour (`--highlight`), used throughout as a fill behind dark `--ink` text: a highlighter-marker stroke behind the lower part of each title (`<span class="mark">`, defined in `theme.css`, so it overlaps the bottom of the letters like a real highlighter), the "work in progress" tag, hover states on buttons and links, the date in the detail panel and the label of the selected marker. Never use yellow as text or as a thin line on ivory (1.06:1), and never as a category colour.
- Accessibility is a requirement (WCAG AA): text 4.5:1 against its background, dots and bars 3:1 against the surfaces behind them. Bars are solid category colours with `--on-bar` text, never a pale tint under dark text. Check every new chart (compute the ratios, do not judge by eye) and never use colour alone to tell categories apart: always add a label or legend.
- Light only: the user does not want a dark mode, so do not add `prefers-color-scheme` or dark variants.
- Secondary surfaces (`--panel`, `--note-bg`, `--band`, `--line`) are light violet tints (hue about 256). Never make them by darkening ivory (turns khaki, the user called it muddy), and keep the hue at about 256: grey-lilac read as pink and blue-grey read as too cold, the user asked for "more purple".
- Borders: the user lifted the old no-border rule, then said the result had "too many borders, all very dark and thin". So use very few. Separate things with spacing and tone. Keep only a handful of deliberate ones, and make them thick and soft, never dark hairlines: the chart frame (3px, `--rule`), the coloured rule under each category caption (3px), the coloured top edge of the reading panel (6px), and the left bars on notes (5px). No outlines on buttons or chips, no rules between rows or panel sections. Do not go back to faint tone-on-tone stripes either (the user called that sloppy and "basic AI work"). Aim for editorial, designed work.
- Accessibility goes beyond contrast. Never rely on colour alone, for anything (the user pointed out that colour-blind and low-vision people could not use the first country cues). Each country is told apart by its row label (text), a marker shape (filled circle, open diamond, filled square, filled triangle: solid versus open is the strongest cue), a bar pattern (plain, stripes, dots, lines) and a label style that differs in brightness (dark filled, light filled). Pressed buttons show a tick and a thick underline as well as the yellow. The selected marker has a heavy ink ring and a highlighted label. Check new work in greyscale (apply `filter: grayscale(1)` to the page).
- Also required: click targets at least 24px, text at least 12px, a visible 3px focus ring, a skip link, a polite status message when something is selected, `main` and labelled regions, and a plain List (table) view that shows the same events as the chart. Respect reduced motion and forced-colours mode.
- To change the look of the whole site, edit `theme.css`. Layout styles that only one chart uses stay in that chart's file.
- New charts: self-contained HTML, lowercase hyphenated filename (`topic-name.html`), relative paths only (for example `data/results.csv`), no spaces in filenames. Match the existing timelines: Roboto (sans serif only, no serif fonts), readable on a phone.

## Publishing
- Pushing to `main` updates the live site within a minute or two.
- Ask the user before every `git push`. Command-line git is not signed in to GitHub, so the user may need to click Push origin in GitHub Desktop.
